# 洗护证据边界与回答评测

日期：2026-11-02。当前工作围绕已复现的原问题改写、未知材质和整件衣物处理许可，不新增未经审核的洗护事实。

## 可信问题约束

`QuestionContext` 为不可变的当前轮上下文，包含 owner、conversation、原始问题以及可信入口读取的选中衣物和已记录材料。服务入口绑定上下文，图工具节点为直接图调用补充上下文；工具 schema 不允许模型覆盖这些字段。工具闭包及线程执行保留所属调用的上下文，退出和异常时恢复。

模型参数用于调用工具，不能把纯棉问题转换为羊毛问题，不能通过删去“多少厘米”解除具体产品数据要求。选中衣物记录与本轮材料描述不一致时先澄清；用户记录材料和上传资料仍是用户提供的信息，不伪装为厂家核验。

## 支持状态与洗护输出

工具兼容保留原 `answer_status`，新增 `support_status`：

| 状态 | 允许行为 |
| --- | --- |
| `supported` | 返回通过有限范围规则的资料，保留适用条件与来源 |
| `partial` | 说明缺少哪部分；有可安全引用的边界证据时限定展示，不授权缺少条件的处理 |
| `needs_clarification` | 补问洗标、款号、尺寸表等必要信息 |
| `not_found` | 说明当前没有适用证据 |
| `out_of_scope` | 不把衣物背景作为域外问题的来源 |
| `conflict` | 指出材料或用户提供洗标限制冲突，停止授予操作许可 |

这些是明确的材料、产品、动作及来源身份规则，不是通用语义蕴涵模型，`supported` 不能外推为专家认证的整段回答正确率。

洗护事实使用有界的来源原句渲染并带出处，图不会把缺证据的洗护结果再交给模型自由补写操作。混纺、拼接、涂层和装饰的整体处理许可需要整件洗标；明确“不可烘干”或“仅专业干洗”的条件不得由通用材料资料推翻。SHAKEDRY 提取明确排除句，避免普通功能外套的加热或补 DWR 步骤混入。

未知短材质参数也执行相同边界。醋酸、腈纶等可识别名称仍可能缺少已审核事实；能识别不等于有足够证据。上传量衣指南须包含匹配款号、尺码、维度与数值，不能只因带 `document_id` 就通过具体尺寸检查。

## 评测独立性与审读

原 23 个开发契约原题保留，修复后逐项重放。新建 24 个前瞻问题和 SHA-256 清单，在本次实现前冻结，包含正常问答、标签冲突、未知材料、混纺、具体产品、多轮修正及会话资料。数据见[质量题集](../../evaluation/answer_quality_cases.json)、[冻结清单](../../evaluation/answer_quality_manifest.json)。

通过完整 `AgentService.chat` 生成最终正文、引用和追踪，再分别记录有限文本判据与模型辅助审读。模型审读检查正确性、忠实度、引用支持性和合理追问，保留理由、无依据结论与无效/超时记录。审读结果不能代替独立人工复核；当前使用同一配置模型的独立调用上下文，并非不同模型或外部专家验证。

题集是项目作者编写，部分知识来源也在开发题中使用过，因此不是来源分组独立的外部盲测。一旦分析结果并据此继续修改实现，该版本须转为回归，首次结果保留；不得把调优后的重跑结果继续称为未知测试。

评测同时导出 `*.review-template.json`，包含逐题回答、参考资料、来源和判据，人工评分留空。没有实际人工审读时，不输出“人工正确率”。

```powershell
python -m evaluation.rag_critical --output artifacts/local/critical-new.json --require-pass
python -m evaluation.answer_quality --output artifacts/local/quality-offline-new.json
python -m evaluation.answer_quality --online --model-review --config-root "dist/personal/出行衣橱助手" --output artifacts/local/quality-online-new.json
```

离线模式不调用外部模型；在线模式使用合成衣柜、模拟天气与 BM25，真实模型及审读消耗单独记录。首字、并发吞吐、真实用户分布和长期稳定性不在本轮范围内。

首次结果发现了仅查询“羊毛”而丢失具体动作、资料/材料齐备仍要求选择单品、分层职责被当成搭配请求、普通知识任务误用洗护工具等问题。分析后继续修复，因此[使用记录](../../evaluation/answer_quality_usage.json)已将题集转为回归；不能把最终 24/24 宣称为独立保留集准确率。

引用身份判据的初版仅依据稀疏预标 ID，后改为核对所有已审来源的 URL 白名单，另保留引用支持性的审读维度。版本 2 在报告中标明，首次结果没有覆盖。因实现与判据均有变化，不将 16/24 → 24/24 的全部变化归因为业务算法提升。

通用收纳前提只为已审核的 `storage-dry-before-fold` 设有限例外，允许在材质问题中补充“完全干燥后收纳”。它不授予任何干燥方法或受热许可，也不开放未知材料的通用洗护操作。SHAKEDRY 抽取条款使用对应的排除段引用范围，避免展示普通外套许可范围造成误解。

已逐题给出[实现者证据核对笔记](../../artifacts/reports/rag/answer-quality-author-audit-20261102.json)，明确审读者参与实现，不作为独立质量评分。外部独立人工正确性、忠实度及引用支持性仍待复核；[逐题审读包](../../artifacts/reports/rag/answer-quality-release-online-20261102.review-template.json)已包含回答、资料和空评分字段。
